## P0 — Adjudicate semantic 🟠 + architecture findings with Opus, not Haiku-only Verify

**Root cause of every FP class below.** The Verify stage is Haiku; Adjudicate is budgeted Opus but only
covers the contested/🔴/architecture tail. The leaked FPs were 🟠 *semantic* findings that Haiku-Verify
accepted and Opus never re-graded. Precision ladder this run: Haiku (called all 5 v1.1 🔴 real) ≪
hand-analysis ≪ Opus (1/5). The Opus re-check found 9 FPs among 21 contested v1.2 findings that Haiku had
passed.

- **Fix:** route ALL architecture findings + 🟠 *semantic* findings (`typed-errors-only`,
  `graceful-shutdown`, `band-*`, `cross-band-*`) through Opus adjudication — extend the current
  `architecture || 🔴 always-adjudicate` rule to `architecture || 🔴 || (🟠 && semantic)`. Keep
  mechanical and clean-pattern 🟡/🔵 on Haiku.
- **Budget:** semantic 🟠 was 24 findings this run — size the Opus budget accordingly (or raise only the
  Verify model for semantic rule-groups instead of widening Adjudicate).
- **Where:** Verify + Adjudicate stages.

## P1 — Architecture / band lane over-flags type-only imports & allowed dependencies

All 3 architecture findings + several 🟠 band findings were Opus-rejected:
- `band-wrong-placement` on type-only imports in files that are in their CORRECT band (`config.ts:5`;
  `s3-raw-storage.ts:11` and `store-raw-replay.ts:9` — storage consuming discovery's `ReplayCandidate`
  type is allowed by the §A fences).
- `cross-band-type-in-types-dir` on same-tier imports (`payload.ts:8`, `staging/types.ts:1`) — the rule
  targets an UPWARD cross-band import (its §A #5 example: adapter `evidence/` reaching up into
  orchestration `run/`), not a same-tier `storage/`↔`staging/` type import.

- **Fix:** (a) exempt `import type { … }` from the band/fence rules, or at minimum stop double-flagging one
  import with two band rules; (b) make `cross-band-type-in-types-dir` fire only on *upward* cross-band
  edges, per its own definition; (c) `band-wrong-placement` must consult the §A band table's allowed
  consumers before flagging.
- **Caveat to resolve:** one rejection cited the code-review skill's band-suspension, which this audit
  *intentionally overrides*. Document which band findings are in audit scope — the fetcher's five-band
  layering is approved (2026-06-13), so genuine upward/placement violations stay reported; the
  misapplications above are not those.
- **Where:** Scope (layerMap / fence extraction) + Structural lane + per-file band rules in Find.

## P2 — `graceful-shutdown` fires on resource construction

`run-once.ts:104` `createStoreRawResources(...)` was flagged — that is construction, not a shutdown path.
The daemon `watch.ts` holds the real SIGTERM/SIGINT seam + `try/finally` dispose; `run-once` is a one-shot
CLI that sets `process.exitCode`.

- **Fix:** scope the rule to actual signal-handler / teardown paths; do not flag resource factories.
  Distinguish one-shot CLI from daemon entrypoints.
- **Where:** rule `howToDetect` in the Scope catalog (Find-lane rule).

## P2 — `typed-errors-only` fires inside Zod `.transform()` throws

`config.ts:26` `throw new Error("Expected boolean-like value")` lives inside a Zod `.transform()` consumed
via `safeParse`, which wraps it into a typed `ConfigValidationError` — the raw Error never escapes. Also a
**self-contradiction**: a separate finding declared `config.ts:26` out-of-scope while this one flagged it.

- **Fix:** (a) exempt throws inside Zod `transform`/`refine`/`superRefine` callbacks that reach a
  `safeParse` boundary; (b) add a cross-finding contradiction/dedup guard so one `file:line` can't be both
  flagged and declared out-of-scope.
- **Where:** rule `howToDetect` (Scope) + the dedup/assembly step.

## P3 — `test-naming-does-not-start-capital` logic inversion

Flagged `test("MD: a full rate-limited window …")` — which DOES start with a capital. The detection is
inverted.

- **Fix:** flag only names that do NOT start with a capital. Correct the rule's `howToDetect`.
- **Where:** Test lane / test catalog rule.

## P3 — `test-no-paired-test` fires on out-of-scope scripts

`scripts/capture-golden-fixtures.ts` was flagged — it sits outside `tsconfig`/`knip`/`depcruise` scope and
the coverage gate (human-run capture utility, never executed by the pipeline).

- **Fix:** exclude `scripts/` (and other out-of-tsconfig-scope paths) from the test-pairing requirement.
- **Where:** Enumerate (scope exclusion) + Test lane.
