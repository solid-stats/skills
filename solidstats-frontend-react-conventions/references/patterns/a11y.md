# Accessibility

Target **WCAG 2.2 AA** minimum, AAA-quality where practical (brief). Accessibility is the #2 quality
priority after UX continuity — ahead of SEO and polish. Ark UI provides the accessible headless
primitives (dialogs, menus, tabs, selects, tooltips, popovers).

## Controls & forms

- Form fields have **visible labels**, helper text where needed, and associated errors; errors appear
  near the field, are announced accessibly, and include recovery guidance. No naked inputs.
- **Icon-only controls require an accessible name**; a tooltip is not a substitute. Decorative icons are
  `aria-hidden`.
- Buttons default to `type="button"`; forms use a semantic `<form>` for Enter→submit.
- Loading states block duplicate submit/upload actions.

## Keyboard & focus

- **Full keyboard support**: menus, forms, dialogs, tabs, tables, filters, pagination, moderation
  actions. **No keyboard traps.**
- **Visible focus** on every interactive control; focus must not be hidden behind sticky headers,
  toolbars, or fixed panels.
- Custom option/menu/listbox markup needs role/aria/focus behavior and keyboard handling (`Enter`,
  `Space`, arrows, `Home`, `End`) — prefer the Ark UI primitive over hand-rolling.
- **Route changes manage focus** for screen-reader users; **table sort/filter state is announced**.

## Structure & contrast

- Skip links + semantic landmarks; a logical heading hierarchy with **one meaningful H1** per page.
- Contrast: **4.5:1** normal text, **3:1** large text and UI graphics. **Never convey meaning by color
  alone** (pair status color with text/icon). Status color comes from the token system with checked
  contrast (see `styling.md`), never inline hex / white-on-light.

## Dynamic content

- Dynamic updates, upload/progress, reconnect, and async errors use appropriate **live-region**
  behavior **without stealing focus** (critical for the SSE updates — see `realtime.md`).
- Modal/fullscreen surfaces use the Ark UI `Dialog` with a portal, a localized title, controlled
  open/mount, and lazy mounting; fullscreen inerts the main content.
- Charts/microcharts: `figure` + a hidden text summary; don't rely on color alone in a legend.

## Targets & motion

- Touch targets **≥ 44×44 CSS px** for primary controls where layout allows; never below the WCAG 2.2
  minimum target size.
- Respect `prefers-reduced-motion` — non-essential animation is dropped (see `performance.md`).

Review flags:

- A naked input / icon-only control without an accessible name; a tooltip used as the only label.
- A focus trap; an invisible focus state; focus hidden behind a sticky element.
- Meaning conveyed by color alone; contrast below 4.5:1 / 3:1.
- More than one H1, or no meaningful H1; missing landmarks/skip links.
- A live update that steals focus or isn't announced; a custom widget missing keyboard handling.
- A primary touch target below 44×44; animation that ignores `prefers-reduced-motion`.
